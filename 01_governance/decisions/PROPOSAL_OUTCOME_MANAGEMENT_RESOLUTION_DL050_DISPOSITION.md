# DL-050 (DISPOSITION DRAFT) — Resolve "Outcome Management" (define or retire)

**Status:** **DRAFT — pending Owner Ratification.** Owner-directed (KIA-4, `OSLO_KNOWLEDGE_INTEGRITY_AUDIT_001`). **Resolves no ontology unilaterally; routes the canon decision to the owner.** Per `CLAUDE.md` (do not resolve ontology conflicts unilaterally; do not introduce doctrine).

---

## 1. Finding (evidence)

**"Outcome Management" is NOT DISCOVERABLE as a defined OSLO concept.** A repository sweep finds **no definition and no substantive usage** — the term appears only in audit/index artifacts that flag it as missing. By contrast, the **canonical outcome-family is defined**:

- **Outcome Integrity** — doctrine (DL-002): *coherence between Intended Reality and Current Reality*; `canonical_definitions.md` §88, + Outcome Integrity **Policies** and **States**.
- **Outcome Orchestration** — `canonical_definitions.md`, `ontology/ontology_registry.md`.
- **Outcome Confidence** — `models/OUTCOME_CONFIDENCE_*`, DL-043, Evaluate.

"Outcome Management" was listed (e.g., in the KIA Domain-2 concept set) as if canonical, but the canon does **not** contain it.

## 2. Why this matters (the risk)

An **undefined-but-referenced** term is a drift magnet: a future Claude Code instance (or contributor) may **invent** a definition to fill the gap — exactly what the Anti-Assumption Protocol forbids. Worse, **"Management" connotes acting on / controlling / automating outcomes**, which **conflicts with OSLO's epistemic posture**: OSLO **preserves understanding and outcome integrity** and **advises — it never acts, governs, or automates** (DL-043/047 invariants; Authority inactive in R1). Adopting "Outcome Management" as canon risks importing an action/automation framing OSLO explicitly rejects.

## 3. Options (owner chooses)

- **Option A — Define it (distinct concept).** Owner supplies a definition and its relationship to Integrity/Orchestration/Confidence, and confirms it does **not** imply autonomous action. *Use only if the owner genuinely intends a separate concept the canon currently lacks.*
- **Option B — Retire & map (recommended).** Declare "Outcome Management" a **non-canonical term**; **map it to existing canon** — use **Outcome Integrity** (for the "keeping outcomes coherent" sense) and/or **Outcome Orchestration** (for the structural/coordination sense). **Add it to `CANONICAL_GLOSSARY.md` banned synonyms** ("→ use Outcome Integrity / Outcome Orchestration; OSLO does not 'manage'/act on outcomes").

## 4. Recommendation

**Option B (retire + map + glossary-ban).** There is no definition, no usage, and a real **semantic conflict** ("management" ⇒ action/control) with OSLO's never-acts model. Mapping to the established Integrity/Orchestration terms preserves intent without inventing a concept or weakening the epistemic posture. Adopt Option A **only** if the owner affirmatively intends a new, distinct, non-action concept.
