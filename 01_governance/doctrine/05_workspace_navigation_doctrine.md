# Workspace & Navigation Doctrine

## Primary Principle

Understanding is the center of the system.

Artifacts support understanding.
Understanding does not support artifacts.

---

# Primary Navigation Structure

Recommended top-level navigation:

- Understanding
- Artifacts
- Attention
- Simulations
- Evolution
- Governance

---

# Understanding Workspace

Primary center workspace:
What OSLO Understands.

This includes:
- confidence
- integrity state
- key concerns
- intended vs current reality
- recommendations
- understanding evolution

---

# Artifact Layer

Artifacts remain:
important but subordinate.

Primary artifact categories:
- Intent
- Context
- Execution
- Schedule
- Resources

---

# Attention Queue

Persistent operational intelligence surface.

Includes:
- ambiguity
- drift
- feasibility concerns
- unresolved governance
- interpretation conflicts

---

# Adaptive Workspace Doctrine

OSLO should be:
conceptually stable,
operationally adaptive.

Workspace focus adapts based on:
- integrity condition
- unresolved concerns
- governance state
- user role
- recent changes

---

# Companion Intelligence Panel

OSLO chat should exist:
contextually.

Recommended placement:
right-side adaptive companion panel.

Conversation supports understanding.
Understanding should not support conversation.

---

# Persistent Confidence Shell

Confidence should remain globally visible.

Confidence is:
a persistent epistemic shell,
not a report page.
