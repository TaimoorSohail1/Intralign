## What this track is

An **intermediate release between R1 and R2**, sequenced while the dev team builds and tests R1
and **before** the R2 build begins. It carries **owner-directed additional enhancements** plus (in a
**later** session) fixes/enhancements driven by R1 testing.

## Scope discipline (this session)

- **Enhancements only.** The **R1-test-driven fixes** bucket is **deferred to a later session**
  (owner decision, 2026-07-14). No test-fix intake is stood up here.
- **Enhancements arrive via a series of owner chat prompts** (owner decision, 2026-07-14) — I do **not**
  pre-populate scope from the mined backlog. Each prompt is one (or more) enhancement(s) to process.

## How each enhancement prompt is processed (grill mini-cycle)

For every enhancement the owner sends:

1. **Scan evidence** — read the relevant canon (doctrine > constitution > implementation) and existing
   grill artifacts before proposing anything. Never infer a spec gap (Anti-Assumption): escalate it.
2. **Canon check** — grep for existing ratified values/terms (tiering, MON-*/UP-*, glossary/DL-*) so no
   product number or term is invented or drifted. Preserve canonical terminology (DL-053).
3. **Decision packet** — narrow, recommendation-bearing questions; unanswered recs are accepted, only
   overrides change them. Lock accepted/overridden decisions in `decision-log.md`.
4. **Contradiction handling** — if it conflicts with signed-off slices/canon/theme/routes/data/AI
   behavior, open a `contradictions.md` record and ask the one A/B/C/D question; never silently overwrite.
5. **Build** — delegate slice docs + cumulative prototype updates to a **worker subagent**; keep the
   one theme; no backend/server/real API/real auth/real DB/real AI.
6. **Signoff** — present the prototype/docs for owner review; lock or reopen per feedback; re-signoff any
   impacted signed-off slice.
7. **Governance** — canonical changes route through **Framework 001** → branch → PR → green doc-integrity
   gate → **owner** merge; land via `dl-land` (never the web form). Never push to `main`. AI recommends;
   only the owner ratifies.
