## 2. The invariant that holds it together

- **Same loop, different evidence.** All three stages run the **same seven-responsibility cognition loop**, differing only in the *evidence* it consumes: plan documents (Planning) → execution-system interaction (Execution) → execution telemetry / outcome KPIs (Validation). **No new responsibility is introduced.**
- **OSLO stays the cognition layer in all three.** It ingests outcome/execution signals as **Attested** evidence (`Perceive`, provenance = the source system), produces **Derived** understanding (`recompute`, CHR-appended), and surfaces **advice**. It **never becomes the executor or the validator-of-record** — "advise proposes, never disposes"; execution monitoring feeds the **Current-Reality** signal, not a parallel truth path.
- **Maturity arc.** Confidence Maturity (Doctrine 04) — Initial → Expanded → **Validated → Continuous** — is the arc this lifecycle traverses; "Validation" corresponds to the **Validated/Continuous** maturity, reached when real outcome evidence closes the loop.

## 4. Boundaries — what this is **not**

- **Not a new primary architectural axis.** The architecture stays responsibility-primary (DL-053); the seven responsibilities are the units of work.
- **Not a workflow-phase model of the epistemic states.** Doctrine 04 is explicit: the Outcome Integrity States are "**epistemic and governance states, not workflow phases**." This crosswalk overlays a communication narrative; it does **not** convert those states into phases.
- **Not doctrine.** Every row cites existing canon; it introduces no concept, structure, or responsibility.
- **Not an R1 scope change.** Execution and most of Validation are **forward** (Doctrine 10 Phases 0–4; Pro+ execution monitoring is the first increment). **R1 remains Planning.**
