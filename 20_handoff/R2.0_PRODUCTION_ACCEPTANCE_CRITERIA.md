# R2.0 — Production acceptance criteria

**Purpose.** Define what a build must satisfy to be accepted for production, so that "tested" becomes
a claim someone can check rather than an auditor's judgement. Written because the 2026-08-29/31 audit
was **self-directed**: broad coverage, but I chose what to test, and that is not the same as a build
having passed a defined bar.

**Zone.** `20_handoff/` — co-governed. The owner sets the obligations; **engineering authors the
realization** (F002 §9.5, DL-235). Nothing here specifies CI topology or test frameworks.

**Status.** DRAFT · **AI-drafted; ratifies nothing.** Routes Backlog → Proposal → Review → Decision
under Framework 001.

**Depends on:** owner rulings 2026-08-30 (ruling 4 — RED-proof via the GT register; ruling 5 —
validation cites gate output) and `PROPOSAL_F002_S6_…_DL243_DRAFT.md` §6a–§6g.

## 2 · EXECUTION ROUTES

Owner ruling 2026-08-30: **automated twins plus a documented manual walk.** Every criterion carries
exactly one route.

| route | definition | ruling |
|---|---|---|
| **TWIN** | A server-side test asserting the invariant on the real backend, which **fails when the invariant is violated**. | Ruling 4 · DL-243 §6c |
| **WALK** | A documented manual step with a stated RED condition, executed against the deployed build and cited in the validation report. | Ruling 5 · DL-243 §6d |
| **PENDING-SUBJECT** | The invariant's subject does not exist yet. **Not a pass. Not a skip.** | DL-243 §6b |

⚠️ **A criterion may not be marked satisfied by the route it was not assigned.** A WALK does not
discharge a TWIN obligation, and a green TWIN does not discharge a WALK.

### 2a · Route assignment, by observability

MEASURED-BY: per-id classification across all 121 register entries, 2026-08-31.

| observability | count | route |
|---|---|---|
| **UI** — observable by driving the browser | **72** | WALK now; TWIN where the assertion is data-shaped |
| **API** — observable in a network payload | **31** | **TWIN** |
| **CODE** — assertable only in source/CI | **17** | **TWIN** |
| **UNKNOWN** — GT-40 (trace exposure undetermined) | **1** | resolve before assignment |

⚠️ **Two corrections to that table, both of which make it less favourable than it looks:**
- **Several UI rows have a CODE half.** GT-10, GT-14, GT-31 and GT-78 assert *"no path exists"* —
  unprovable by observation. **UI is necessary but not sufficient for these; they need both routes.**
- **GT-39…GT-50 (12 engine invariants) are `pending()`** and cannot be observed at all until the
  L1/L2 sensitivity engine exists. **They are PENDING-SUBJECT, not CODE** — classified CODE only by
  absence of a subject. **Marking them green today would be the skip-as-pass failure DL-243 §6b
  exists to forbid.**

## 4 · WHAT A PASS REQUIRES

A build is acceptable for production when **all** hold:

1. Every **TWIN** criterion is green, and each twin has been **RED-proved** — shown to fail when its
   invariant is violated. *A test that has never failed is not evidence* (ruling 4, DL-243 §6c).
2. Every **WALK** criterion is executed against **that build**, each result citing `MEASURED-BY:` or
   `NOT-MEASURABLE:` (ruling 5, DL-243 §6d).
3. No criterion is in **PENDING-SUBJECT** without an owner ruling accepting it as out of scope for
   this release (DL-243 §6b).
4. The build carries a **resolvable identity** (N-5, DL-243 §6e).
5. Open defects violating a registered invariant are **closed by the twin that proves the fix**, not
   by assertion (ruling 6, DL-243 §6f).

⚠️ **An unfinished gate is not a passed gate** (DL-243 §6a). **Cancellation, timeout and error are
indistinguishable from failure** for acceptance.

### 4a · The criteria set must be executable inside one iteration

**Owner constraint, stated 2026-08-31: releases run on a fixed two-week iteration and a freeze must
occur inside each one.** That binds this document as much as it binds the build.

**A criteria set that cannot be executed within one iteration is not a gate — it is a backlog**, and
it will be skipped under cadence pressure exactly when it matters most.

So:

1. **Every criterion carries a route** (§2) and **TWIN is the default.** A WALK is permitted only
   where the check genuinely needs a human read — first-run comprehension, generated prose, visual
   honesty. **WALK is not a parking space for work nobody has automated.**
2. **The WALK set must be executable in under one working day.** If it grows past that, criteria move
   to TWIN or the cadence absorbs the cost. ⚠️ **Today's WALK set is larger than that** — the
   2026-08-29/31 audit took a full day and covered roughly a fifth of the criteria.
3. **Backfill is sequenced, not deferred.** The 61 untwinned invariants (`GT-58…GT-118`) cannot land
   in one iteration. Each iteration names which move to TWIN; **an invariant with no route and no
   named iteration is PENDING-SUBJECT, which is not a pass** (DL-243 §6b).

⚠️ **The measured gap between this requirement and today: ~25 of 131 criteria exercised, by hand, in
a day, by an auditor who chose them.** That is the distance the twin backfill has to close before the
cadence can carry a freeze every two weeks.
