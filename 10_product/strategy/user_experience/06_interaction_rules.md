# Interaction Rules

## Rule 1 — Progressive Disclosure

Do not expose all complexity upfront.

Expose depth when:
- user asks why
- confidence changes
- governance triggers
- uncertainty matters
- consequence is high

---

## Rule 2 — OSLO Chat Is Contextual

Do not make chat primary navigation.

OSLO companion should understand:
- current view
- selected artifact
- selected issue
- confidence state
- governance context

---

## Rule 3 — Recommendations Require Evidence

Every meaningful recommendation should have:
- source basis
- confidence impact
- affected dimension
- explanation path

---

## Rule 4 — High-Impact Changes Require Rationale

If a user overrides OSLO on a high-impact item:
- capture rationale
- preserve divergence
- update history
- show confidence impact

---

## Rule 5 — Assistive by Default

OSLO should be assistive unless:
- governance policy applies
- critical confidence degradation occurs
- outcome integrity is threatened

---

## Rule 6 — No Silent Canonical Mutation

OSLO should not silently alter canonical understanding.

Changes should be:
- accepted
- approved
- inferred with label
- promoted through governance

---

## Rule 7 — Uncertainty Must Be Visible

When evidence is weak:
show epistemic state.

Avoid false certainty.

---

## Rule 8 — Shared Views Start Lightweight

Shared views should default to:
visibility and understanding.

Deeper collaboration and governance should be progressive.

---

## Rule 9 — Confidence Is Inspectable

Clicking confidence must reveal:
- dimensions
- drivers
- evidence
- history
- maturity limitations

---

## Rule 10 — Workspace Should Stay Calm

Avoid:
- constant alerts
- noisy feeds
- excessive animation
- AI chatter

Escalate only when meaningful.
