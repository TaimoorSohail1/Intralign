# Workflow Specifications

## Workflow 1 — New Freemium Outcome Space

1. User opens Create Outcome Space.
2. User enters text, uploads artifacts, imports export, or selects sample.
3. OSLO runs Fast Pass.
4. OSLO shows Project MRI reveal.
5. OSLO displays initial confidence and findings.
6. OSLO runs Deep Refinement.
7. OSLO updates confidence maturity.
8. User sees activation summary.
9. User enters Outcome Space.

---

## Workflow 2 — Resolve Attention Item

1. User opens Attention Queue.
2. User selects highest-impact issue.
3. OSLO opens companion in Resolve mode.
4. User reviews evidence.
5. OSLO offers actions:
   - clarify
   - accept recommendation
   - assign
   - simulate
   - dismiss with rationale
6. User acts.
7. OSLO recalculates confidence.
8. Timeline records resolution.

---

## Workflow 3 — Edit Artifact With OSLO Assistance

1. User opens artifact.
2. OSLO displays inline diagnostics.
3. User selects diagnostic.
4. Margin card shows:
   - issue
   - confidence impact
   - recommendation
5. User accepts, modifies, or discusses.
6. OSLO updates understanding.
7. Confidence shell reflects change.

---

## Workflow 4 — Confidence Inspection

1. User clicks confidence shell.
2. Confidence Inspector opens.
3. User sees:
   - clarity
   - alignment
   - feasibility
   - confidence maturity
   - primary drivers
4. User drills into evidence.
5. Bottom tray opens evidence/lineage/timeline.

---

## Workflow 5 — Share View

1. User selects Share.
2. User chooses view:
   - executive snapshot
   - artifact review
   - understanding snapshot
   - governance review
3. User selects permissions.
4. Recipient opens lightweight view.
5. Recipient can optionally comment, clarify, or approve depending on role/tier.

---

## Workflow 6 — Governance Override

1. User attempts high-impact override.
2. OSLO detects divergence.
3. OSLO displays:
   - OSLO interpretation
   - user intended change
   - confidence impact
   - policy implications
4. User must provide rationale if required.
5. Override is recorded.
6. Confidence and governance state update.

---

## Workflow 7 — Scenario Simulation

1. User opens Simulations.
2. User enters condition change.
3. OSLO computes projected impact.
4. UI shows:
   - confidence change
   - dimension changes
   - assumptions affected
   - mitigations
5. User can save scenario or convert to alternative outcome model.

---

## Workflow 8 — Understanding Evolution Review

1. User opens Evolution.
2. User selects time window.
3. OSLO compares previous vs current understanding.
4. User sees:
   - confidence movement
   - interpretation changes
   - assumption changes
   - governance decisions
5. User drills into causes.
